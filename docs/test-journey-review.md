# Real-shell journey reorganization review

## Scope and baseline

The baseline is `9fc1604f53de47058972f446822b8e5bf0baf6eb`: 54 Playwright tests in 14 spec files, with 1,826 real-shell test lines and 17 committed PNG baselines. The reorganization changes test ownership and setup reuse, not production behavior, dependencies, CI, authentication or screenshot thresholds.

The suite keeps one disposable host and one worker. Each journey still has a fresh browser context. All existing shell scenarios remain reachable within independent journeys; theme/width variants become named steps rather than separate fresh-shell tests.

## Validation and observations

The unchanged full shell suite passed all 54 tests in 1.7 minutes. The GitHub card pilot passed 12 original tests in 21.8 seconds; the consolidated [cards journey](../packages/dsh-github/test/real-ui/cards.spec.mjs) passed in 10.5 seconds, including host setup/teardown (about 52% less wall time). These are local measurements, not a promised CI speedup.

The pilot retains all 20 named diagnostic captures and their dimensions. Eighteen are pixel-identical; two dark/narrow issue images differ only in 19 or 65 pixels, with a maximum channel delta of 5/255. They are diagnostics, not committed baselines. Image inspection also caught a real same-page hazard: root `color-scheme` changed while mounted field cards retained the previous theme. Native navigation/remount fixed both field images without changing production code or accepting new references.

The pilot preserves all original assertions; existing Vitest suites already own the detailed component variations, so this pass does not add duplicate replacement tests. The completed suite has 17 journeys in 11 files: GitHub 3, Recap 8, Worktrees 2, and one each for Environment, Projects, Jev and OpenRouter. Recap's automatic, selection-diagnostics and bookmark fixtures remain isolated; Worktrees' controlled-clock composer regression remains separate from layout.

The first full candidate exposed two state assumptions. Appearance is optimistic: rapid theme checkpoints can receive an older accepted Host snapshot after the root `color-scheme` initially changes. The [shared theme helper](../tests/real-ui/fixtures.mjs) now waits for the actual Settings acceptance response when the preference changes. Worktrees also retains its selected tab; the journey returns to Chat before the conversation-navigation helper waits for the seed message. The guidance records both findings, scoped HTTP mocks and Recap's page/session cache lifetime. No elapsed-time sleep, hardcoded palette assertion, production reset seam or comparison tolerance is added.

## Final validation

- Two full Playwright runs passed all 17 journeys and all 17 unchanged committed PNG comparisons: 1.1 minutes, then 1.0 minute. Against the local 1.7-minute baseline, this is about 40% less wall time. CI runtime is not measured here.
- All 37 original named diagnostic images remain (35 GitHub plus selection and bookmark details). Thirty-five are pixel-identical to the unchanged full-suite baseline; the other two have the same minor dark/narrow issue differences described above. Baseline paths and bytes remain unchanged.
- All 249 Vitest Browser tests passed across 21 files. The existing Google Drive polling tests emit React `act()` warnings; they are outside this change.
- All 642 affected Node/backend/packaging/fixture tests passed. This includes GitHub, Jev, OpenRouter, Projects, Environment, Recap, Worktrees and the shared real-ui fixture lifecycle/navigation suites.
- Repository wiring and diff whitespace checks passed. Focused formatting checks run on all maintained changed files.
- Independent read-only reviews confirmed retained shell assertions and image names. Review found that the new OpenRouter failure cleanup initially accepted a transient busy/disabled button. Cleanup now waits for the successful removal notice, enabled input and final disabled Remove state. A reversible control forced a failure after Save; the next fresh context verified that the shared credential was not configured. The intentional failure and temporary probe are removed.
